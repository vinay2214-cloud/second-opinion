# S4 · Plane detection and table placement
Verdict: PASS in the emulator. Not tested on a device.
Date / IWSDK version / device or emulator: Tue 10 Nov 2026 / @iwsdk/core 1.1.0-rc.2 / IWER emulator (metaQuest3), room `sunlit_living_room`, emulated hands.

What I tried (in order):
1. Query `XRPlane` entities (documented in `scene-understanding/plane.d.ts`), read `_plane.orientation` and `_plane.polygon`, and use the plane entity's `object3D` for its pose. The emulated room reports 15 planes; the round desk is at height 0.74 m.
2. Pick a table-like plane: horizontal, 0.20 to 0.95 m below the eyes, within 0.8 m of the head. Floor, ceiling and walls are rejected by those limits.
3. Show a pulsing pad the size of the ward (60 x 40 cm). A pinch with the hand ray on the pad, or a poke, confirms (`RayInteractable` + `PokeInteractable`, then the documented `Pressed` tag).
4. After confirming, add `XRAnchor` to the ward root (documented in `scene-understanding/anchor.d.ts`).
5. No plane within 5 s: virtual table 40 cm in front of the head and 40 cm below eye level.
6. Re-centre button on the table edge (5 cm, pinch-ray or poke).

What worked (code snippet or path): `src/game/systems/PlacementSystem.ts`, `src/scene/ward.ts`, `src/scene/bootstrap.ts`, values in `src/scene/config.ts`.

Fallback chosen (if any): none needed. The virtual table is the built-in fallback and is also what a desktop browser shows.

Impact on docs or tasks:
- One addition that is not in the card: if a plane is found but nobody pinches within 15 s, the ward is placed on that plane anyway, so a player who does not know the gesture is never stuck. Value in `src/scene/config.ts` (`confirmTimeoutSec`). Remove it if you prefer a hard wait.
- Unconfirmed, needs the remote Quest tester: (a) whether a real room scan returns the player's table as a horizontal plane at a sensible height, (b) whether a native anchor is actually created (the emulator accepts `XRAnchor` and the ward stays put, but I cannot tell an anchored ward from an unanchored one when nothing drifts), (c) Re-centre after physically moving.
- The SDK keeps one shared anchor for all `XRAnchor` entities and stores its id in `localStorage` (`iwsdk_scene_anchor_uuid`). That is the SDK's own storage use, outside our safe-storage wrapper.
- `iwsdk.config.json` requires `scene` to be a file under `public/scenes/`. I added an empty `public/scenes/ward.iwsdk.scene.json` (outside the card's Allowed files; there is no other way to drop the starter scene). The ward itself is built in code under `src/scene/`.
- The starter files are no longer loaded but still exist: `src/robot.ts`, `src/robot-component.ts`, `src/panel.ts`, `src/components.ts`, `src/assets.ts`, `src/scene-assets/`, `public/scenes/main.iwsdk.scene.json`, `public/ui/`, `public/audio/chime.mp3`. They should be deleted (not in this card's Allowed files). Dropping them also removed a CDN fetch of the starter robot model, so the app now makes no external requests.
- Outside XR the tracked head sits at the origin, so the desktop view uses the browser camera as the viewer.
