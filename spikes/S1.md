Impact on docs or tasks:
- **`@latest` is 1.1.0-rc.2, not 1.0.** There is no 1.0 dist-tag on npm (`latest` and `next` both point at 1.1.0-rc.2). The docs say "IWSDK 1.0". Versions are pinned exactly in `package.json`, so it will not move under us.
- `--no-locomotion` is rejected for `--target ar` (locomotion is already off for AR). `--foreground` is optional; without it `dev up` detaches and keeps running.
- `iwsdk.config.json` is the project authority (scene, components, XR features), not `vite.config.ts`. World options come from `virtual:iwsdk-project`. Scenes are composed in `public/scenes/*.iwsdk.scene.json`; `docs/03` section 4 (target layout) should gain `src/components.ts`, `src/assets.ts`, `src/scene-assets/`, `public/scenes/`, `public/ui/`.
- Import Three from `@iwsdk/core`, never from `three`.
- I removed the template's `@meta-quest/metavr` dev dependency: it controls a USB-connected Quest (we have none) and the scaffolder says it collects usage data. Re-add with `npm i -D @meta-quest/metavr` if a headset appears.
- Partial answer to S8: the emulator **does** simulate hands (named poses, pinch value, scripted reach/grab/carry via `iwsdk xr run-sequence`), and has a `metaVRGlasses` device profile with gaze. It cannot tell us real tracking jitter or frame rate.
- The drive is exFAT: macOS writes `._*` sidecar files. They are in `.gitignore`.
